# 제작 순서와 초기 백로그

같은 게임에 기능과 품질을 누적합니다. 아래는 작업 지시의 원본이며 **G001~G009를 GitHub 이슈로 등록했습니다.** `G번호`는 내부 ID이고 실제 이슈는 아래 표로 연결합니다. 이슈 등록은 구현 완료를 뜻하지 않습니다. 모든 기능은 현재 미구현입니다.

## 1. 마일스톤

| 단계 | 플레이할 수 있는 결과 | 다음 단계로 갈 근거 |
| --- | --- | --- |
| M1 첫 영업·대표 화면 | 작은 매장에 들어가 첫 손님을 받고 대표 좌석을 관찰 | 조작·규칙·웹 아트 파이프라인이 연결됨 |
| M2 첫 20분 | 첫 매출, 두 투자안, 변화 확인, 저장 | 사람이 선택 이유와 결과를 이해 |
| M3 사장에서 운영자로 | 음식·청소·직원 위임·단체석 | 반복 노동이 줄고 새 판단이 생김 |
| M4 작은 완성판 | 12→24석, 7일 시나리오, 요금·보고서·회복 | 처음부터 끝까지 진행·저장·복구 가능 |
| M5 확장 | 60석, 30일·자유 운영, 단골·교대 | 만석과 중후반 선택·성능이 유지됨 |
| M6 출시 마감 | 시각·조작·사운드·성능·저장 마감 | 실제 배포물에서 주요 오류 해결 |

출시 일정을 확정하지 않습니다. 첫 기능 연결과 두 번째 에셋 변형 제작 시간을 측정한 뒤 반복 가능한 작업량으로 견적을 갱신합니다. 이전의 11–19주 추정은 확정 일정으로 사용하지 않습니다.

## 3. 구현 가능한 작업 계약

### G001 — 첫 매장

목적: 브라우저에서 입구·좌석열·카운터를 걸으며 조작할 수 있습니다. TypeScript/Vite/Three와 DOM UI, 명령 경계, 실제 설치·빌드·검증 명령을 만듭니다. 상세 지시는 [첫 매장 작업서](../tasks/001-first-cafe.md)에 있습니다.

완료: 이동·충돌·카운터·배치 모드·일시정지의 입력이 겹치지 않고 개발/프로덕션 빌드가 열립니다. 하위 경로의 자산 로딩도 확인합니다. 경제·재미·최종 그래픽의 완료를 주장하지 않습니다.

### G002 — 첫 손님과 첫 매출

목적: 자리가 영업에 사용되고 손님이 돈을 내는 변화입니다. 고객은 입장, 좌석 예약, 접근, 착석, 이용, 퇴장을 거칩니다. 첫 요금은 단순 종료 결제로 시작할 수 있습니다.

포함: 좌석 하나의 점유, 이용 종료 지출/수입 규칙, 입·퇴장 피드백, 돈 표시. 제외: 단체·음식·선불권·복잡한 성향. 불변식: 중복 점유·중복 매출 금지, 경로 실패 시 예약 반환. 검증: FIRST-SALE, 좌석 없는 경우, 종료 재입력, 같은 sim tick의 1/4배속 결과. 사람 확인: 영업 중임을 화면에서 이해하는지.

### G003 — 대표 좌석 완성

목적: 한국 PC방의 실제 비율·재질·빛·인물 자세를 체감합니다. 한 좌석 세트와 통로 대표 구도를 최종 방향으로 만듭니다.

포함: 웹용 GLB, collider·착석점, 재질·조명, idle/walk/sit 최소 동작, 출처·export 기록. 제외: 전체 제품 수와 매장 장식 확장. 검증: 가까운 시점·이동 중 관통/발 미끄러짐, 12/24/60 반복 배치 비용, 두 번째 변형 제작 시간. 자료가 부족하면 자체 제작 임시 자산의 한계를 명시합니다.

### G004 — 두 투자안과 첫 재미

목적: 장비 또는 서비스·쾌적함 중 하나를 개선하고 왜 달라졌는지 이해합니다. 시작 가정은 장비/모니터 개선과 의자·쾌적함 개선입니다. 실제 초기 데이터와 손님 요구에 맞춰 두 선택을 구체화합니다.

포함: 작은 실존 제품 카탈로그, 기준일/근거 상태, 구매·설치·현금 차감, 최소 두 고객 성향, 실제 계산한 불만 원인. 제외: 모든 SKU, 정확한 벤치마크 FPS. 불변식: 부족한 현금/비호환 구매 차단, 재입력 이중 지출 금지. 검증: INVEST-2 및 다른 고객 성향 두 조건. 사람 확인: 선택 이유, 효과 인지, 다음 투자 욕구. 수익 숫자만 바뀌고 현장 차이가 없으면 완료 범위를 다시 점검합니다.

### G005 — 저장과 복원

목적: 영업을 멈췄다가 같은 매장을 이어갑니다. IndexedDB, 마지막 정상 백업, JSON 내보내기/가져오기, 버전 검증을 구현합니다.

포함: 고객 이용·장비 투자 상태, RNG/시각, 스키마 검사, 오류 안내, 동시 탭 충돌 방지. 이후 음식·직원 상태는 해당 기능 PR에서 저장 계약을 함께 확장합니다. 검증: SAVE-MID, 손상 JSON, 미래 버전, 저장 공간 오류, 정상 슬롯 보존, 새로고침 후 이중 매출 없음. 브라우저 저장 삭제 후에는 JSON 백업 없이 복구를 보장하지 않습니다.

### G006 — 음식·청소·직접 작업

목적: 짧은 행동으로 영업 문제를 해결하는 손맛을 만듭니다. 라면·음료부터 주문·조리·전달·재고, 퇴장 후 책상 정리를 연결합니다.

포함: 주문 상태, 사장 claim, 짧은 조작·소리·시각 피드백, 지연 사유. 제외: 세밀한 요리 미니게임과 재료 수십 종. 검증: 마지막 재료 경쟁, 주문 취소, 완료 재입력, 저장 도중 업무 복원. 사람 확인: 한 번의 작업이 즐겁고 반복이 피곤해지는 시점. 길어진 바닥 닦기 같은 반복량으로 플레이타임을 늘리지 않습니다.

### G007 — 직원·단체석·역할 변화

목적: 반복 업무를 맡기고 매장 구성·피크 대응을 고민합니다. 첫 직원은 사장과 같은 업무 규칙으로 청소/서빙합니다. 단체 고객은 연결된 좌석을 찾습니다.

포함: 고용·업무 우선순위, claim 반환, 연속 좌석과 이탈 사유, 인건비의 예정 지출. 제외: 복잡한 직원 감정·교대·훈련 트리. 검증: ORDER-RACE, GROUP-3, 직원 해고/막힌 경로, 저장 중 담당 업무. 사람 확인: 첫 직원이 시간을 돌려주는 보상인지, 빈 시간에 새 운영 고민이 생기는지.

### G008 — 요금·비용·회복

목적: 현금과 영업 성과를 이해하고 잘못된 투자에서도 회복합니다. 기본 요금·시간권·선불 잔액과 이용 매출을 구별하고, 주요 비용·예정 지출을 보여줍니다.

포함: 일일 보고서, 단순 임대료·급여·전력 모델, 장비 매각·메뉴 축소·영업 조정, 기본 고장/수리. 제외: 세무 신고·전표 입력·은행 상품 세부. 검증: 충전/사용 이중 매출 없음, 할인/환불의 잔액 보존, 결산 중복 없음, 파산 직전 회복 시나리오. 비용 수치는 현실 참고와 게임 가정을 표시합니다.

### G009 — 작은 완성판

목적: 7일 동안 12→24석을 확장하고 한 판의 변화를 경험합니다. 진행 안내, 목표·보고·이어하기, 기본 음향·설정·접근성을 마감합니다.

포함: 세 가지 운영 방향이 성립하는 수요 조건, 첫 경험 튜토리얼, 입력/감도/음량/품질 옵션, 실제 Pages 빌드. 검증: 처음부터 끝까지 사람 플레이, 주요 저장 회귀, 24석 피크, 배속, 배포 URL 새로고침. 기한은 강제 폐점보다 평가·정산 시점으로 표현합니다.

### G010 — 확장과 출시 품질

목적: 60석·30일/자유 운영에서 관리 재미를 유지합니다. 직원을 늘려도 단순 클릭이 늘지 않도록 교대·단골·피크 변화를 추가합니다.

G010은 미래의 묶음 작업입니다. G009 결과 후 교대·단골·60석 부하·콘텐츠·마감으로 다시 나눕니다. 현재 한 에이전트에게 전체를 한 번에 지시하지 않습니다. 검증: PEAK-60, 장기 메모리, 저사양 옵션, 세이브 이전, 중후반 사람 플레이. 성능 미달이면 [검증 문서](../quality/validation.md)의 순서로 병목을 수정합니다.

## 4. 매번 보지 않아도 되는 것

도시 전체, 다점포, 멀티플레이, 원작 게임 직접 실행, 정교한 부품 조립, 모든 하드웨어 카탈로그, WebGPU 전용 그래픽은 첫 완성판 밖입니다. 새로운 아이디어는 현재 기능을 늘리는 대신 이후 후보로 기록하고 실제 문제·효과를 먼저 확인합니다.
