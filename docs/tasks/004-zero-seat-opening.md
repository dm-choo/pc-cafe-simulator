# Z001 — 0석 창업과 현실풍 재질

최신 사용자 요청: 미리 갖춰진 12석 대신 아무 설비도 없는 0석에서 직접 시작하고, 더 사실적인 그래픽을 사용한다. G004의 선행 구매·설치 구현이며 두 투자안/고객 성향/실존 제품 카탈로그의 완료를 뜻하지 않는다.

## 플레이 변화

- 빈 임대 공간, 카운터·좌석·재고 0. 시험 시작 자금 400만원.
- N 구매: 카운터 40만원, 좌석 패키지 120만원. 모두 기준일 실가격이 아닌 임시 밸런스.
- B 설치: 카운터 고정 위치와 12개 좌석 구역. 확정 때만 모델·스크린·충돌·좌석 상태가 동시에 생긴다.
- 카운터와 좌석 1개 이상을 설치해야 개점한다. 실제 설치한 자리만 고객이 예약하고 이용한다.
- 현금 = 시작 자금 − 구매 지출 + 영업 매출. 구매/설치를 분리하고 중복 설치·재고 음수·부족 현금을 막는다.
- 영업 중/고객 잔류 중에는 설치하지 못한다. 사장과 겹치는 설치도 차단한다.
- Poly Haven CC0 목재·콘크리트·벽의 1K color/normal/roughness, 공유 환경 반사와 조명 조정.

## 검증 계약

1. 규칙: 초기 0, 개점 조건, 구매/재고/설치 원자성, 한도, 영업 중 설치 제한, 첫 결제 현금 보존.
2. 충돌: 비어 있던 카운터 구역 통과 → 설치 후 차단 → 초기화 후 통과.
3. 브라우저 ZERO-START: 실제 구매 UI, 미설치 재고, 사장 겹침 차단, 첫 좌석 설치, 새로고침 초기화.
4. FIRST-SALE: 실제 구매/설치를 거쳐 첫 착석과 1,500원 수입. BASIC-12는 초기 0석에 맞춰 회귀 검사한다.
5. 시각: 빈 공간·구매 UI·한 좌석 설치·고객 착석 화면을 직접 검토한다. 스크린샷은 재미나 실제 GPU 60fps의 증거가 아니다.
6. 배포: main의 검증된 빌드를 Pages에 게시하고 공개 URL에서 같은 브라우저 검사를 실행한다.

## 범위 밖

자유 배치·회전·철거/매각, 배송 애니메이션, 개별 PC 부품 조립, 임대 계약/대출, 저장, 두 투자안의 수요 차이, 최종 인물·애니메이션, KTX2와 실 GPU 성능 검증은 후속 작업이다. 단순 구매 횟수를 늘리는 대신 다음에는 저장과 실제 선택·고객 반응을 연결한다.
