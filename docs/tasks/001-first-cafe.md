# G001: 브라우저에서 첫 매장을 걸어 다니기

상태: **ready, 미구현**. GitHub 이슈: [#1](https://github.com/dm-choo/pc-cafe-simulator/issues/1). 선행 기능 없음.

## 목적

한국 PC방의 입구·좌석열·카운터를 직접 걸으며, 현장 조작과 경영 화면이 연결되는 개발 기반을 만듭니다. 다음 작업 G002가 같은 프로젝트에 첫 손님을 넣을 수 있어야 합니다.

## 관련 문서

- [게임 계획](../product/plan.md): 6·7·9장.
- [아키텍처](../architecture/overview.md): 상태 소유권, 입력·시간·공간.
- [아트 제작](../art/pipeline.md): 대표 구도·크기·에셋 ID.
- [검증](../quality/validation.md): BASIC-12와 빌드/브라우저 구분.

## 포함 범위

- TypeScript, Vite, Three.js WebGL2, 최소 React DOM UI. 실제 버전 확인 후 package-lock과 지원 Node 버전 고정.
- 12석을 놓을 수 있는 한 매장. 입구·좌석열·카운터·작은 주방의 구조.
- 1인칭 이동·보기, 단순 충돌, 가까운 물체 선택, 카운터 열기/닫기.
- 위에서 보는 배치 모드와 일시정지. 이번에는 배치 미리보기와 선택 피드백까지 가능.
- 키보드·마우스 입력 모드 전환, ESC·포인터 잠금 해제, 설정 화면.
- sim과 render/UI 경계, 고정 스텝과 탭 숨김 정지, 개발 장면 reset.
- 실제 개발·빌드·타입 검사·핵심 스모크 명령과 CI. 하위 경로 자산 로딩 확인.

임시 형상으로 공간을 시작할 수 있으나 크기·좌석 밀도·눈높이는 아트 계약을 따릅니다. 최종 현실풍 재질·인물은 G003에서 완료합니다. 경제·고객·음식·세이브·다중 에이전트 인프라는 G001에 넣지 않습니다.

## 완료 조건

1. 새 환경에서 문서화한 설치 명령을 실행하고 개발 서버와 production preview를 열 수 있습니다.
2. 입구에서 좌석 통로와 카운터까지 걸어갈 수 있고 벽을 통과하지 않습니다.
3. 카운터를 열면 이동·시선 입력이 UI와 충돌하지 않으며 닫으면 정상 복귀합니다.
4. 배치 모드와 탭 숨김에서는 sim 시간이 멈추고 복귀할 때 밀린 시간이 한꺼번에 적용되지 않습니다.
5. 새로고침한 production preview에서 자산 404·처리되지 않은 오류가 없습니다. 실제 저장소 하위 경로 `/pc-cafe-simulator/`를 확인합니다.
6. 화면·명령이 규칙 상태를 우회 수정하지 않도록 최소 경계가 존재하고 다음 고객 기능을 넣을 위치가 명확합니다.
7. README·AGENTS·현재 상태의 명령이 실제 실행 결과와 일치합니다.

## 검증과 산출물

초기 npm scripts의 목표는 `dev`, `build`, `preview`, `typecheck`, `lint`, `test`, `test:e2e`입니다. 이름만 만들지 않고 해당 작업에서 실제 역할이 있는 것부터 추가합니다. 빈 테스트를 통과시키거나 없는 검사를 성공으로 보고하지 않습니다.

브라우저에서 이동→카운터→닫기→배치→복귀를 직접 수행합니다. 입구·좌석 통로·카운터 구도 3개를 확인하고 오류·해상도·환경을 남깁니다. CI가 소프트웨어 그래픽이면 목표 GPU 성능 측정으로 쓰지 않습니다. 원격 배포가 막혀도 로컬 production build 검증은 완료하고 차이를 명시합니다.

작업 브랜치 제안: `feat/g001-first-cafe`. PR은 목적, 조작, 실제 검사, 화면, 미구현 범위, G002 시작 위치를 설명합니다.
