# 한국 PC방 타이쿤 — 개발 계획

개정: v0.3 · 2026-09-07 · 가격 참고 기준일: 2026-01-01

## 1. 이번에 확정한 방향

**플레이어가 “내가 진짜 PC방 사장이라면 이렇게 하겠다”라고 생각하며, 자기 매장을 키우는 과정 자체를 즐기는 웹 3D 경영 게임.**

현실성은 투자·서비스·인력·배치 판단을 납득하게 만드는 데 사용한다. 장비 조사나 세부 설정이 실제 플레이보다 커지지 않게 한다. 그래픽은 GTA V를 떠올릴 만한 자연스러운 현실풍 공간과 움직임을 지향하면서, 원활한 성능을 함께 충족한다.

사용자가 추가한 두 메시지는 v0.2의 과도한 정밀 재현 요구를 조정하는 기준이다. BIOS·메모리 프로필·리비전별 추적·치수 오차 검수·모든 과거 가격 증거 확보를 개발 선행 조건으로 두었던 내용을 철회한다. 실제 제품·게임 이름과 2026-01-01 가격 기준, 한국 PC방다운 시각·운영 감각은 유지한다.

최신 사용자 결정(2026-09-07): **처음부터 0석, 카운터와 소유 장비도 없는 빈 임대 공간에서 시작한다.** 시작 자금으로 구매 → 설치 → 첫 손님 → 재투자를 경험한다. 무자본 생존·대출·임대 계약까지 이번 시작 구현의 필수 조건으로 확대하지 않는다. 실제 구현·배포 상태는 [현재 상태](../production/status.md)에 기록하며, 아래 재미·성능 수치는 검증 목표다.

### 네 가지 판단 기준

| 가치 | 개발 중 확인할 질문 |
| --- | --- |
| 재미 | 이 행동을 다시 하고 싶은가? 다음 변화가 기대되는가? |
| 사장다운 판단 | 실제 매장을 운영해도 납득할 만한 고민과 선택인가? |
| 공간에 대한 애착 | 내가 산 장비·바꾼 배치·고용한 직원이 매장에서 눈에 보이는가? |
| 성능 | 손님이 많고 바쁜 순간에도 조작과 화면이 원활한가? |

새 기능은 선택의 재미, 직접 하는 손맛, 꾸미기·소유감, 이해하기 쉬운 피드백 중 무엇을 더하는지 설명할 수 있어야 한다. 장식도 공간의 매력을 높이면 가치가 있다. 모든 물건에 경영 능력치와 별도 조작을 붙일 필요는 없다.

개발사의 공식 스토어 설명을 조사했다. 직접 게임을 실행해 밸런스와 손맛을 검증한 것은 아니다. 아래의 ‘적용 방향’은 확인한 기능을 바탕으로 한 이 프로젝트의 설계 판단이다.

ICS2가 소개하는 폭력배·폭탄·불법 사업 같은 사건은 이 게임의 중심으로 채택하지 않는다. 한국 PC방 운영에서 나오는 단체석 부족, 피크 시간 주문, 장비 교체, 직원 공백으로 긴장과 변화를 만든다. 이는 해당 게임의 재미가 낮다는 평가가 아니라 이 프로젝트가 선택하는 주제다.

참고작의 기능을 전부 합치는 방식으로 범위를 늘리지 않는다. **직접 돌보는 현장감 + 납득되는 투자 판단 + 직원에게 맡기며 달라지는 역할**을 하나의 플레이 흐름으로 연결한다.

## 3. 이 게임에서 재미를 만드는 방식

### 중심 반복

매장을 살펴본다 → 문제나 기회를 알아챈다 → 직접 처리하거나 투자한다 → 손님과 공간이 달라진다 → 수익·여유·애착을 얻는다 → 다음 개선을 계획한다.

돈이 늘어나는 것과 함께 개선의 결과가 현장에서 보여야 한다. 청소한 좌석에 다음 손님이 앉고, 새 모니터가 들어온 구역에 관심이 몰리며, 서빙 직원을 고용하면 밀린 주문이 줄어드는 식이다.

| 재미의 종류 | 실제 플레이 예시 |
| --- | --- |
| 선택 | 전 좌석을 조금씩 개선할지, 프리미엄 구역 몇 석을 먼저 만들지 결정 |
| 손맛 | 장비 설치, 트레이 전달, 책상 정리 후 깔끔해지는 짧고 명확한 반응 |
| 성장 | 주문 하나를 직접 처리하던 사장이 직원·근무표·확장 투자를 관리하게 됨 |
| 소유감 | 좌석 배치·조명·의자·메뉴를 고르고 내가 만든 매장을 걸어 다님 |
| 작은 이야기 | 자주 오는 단체 손님, 늘 같은 메뉴를 주문하는 단골, 직원의 숙련 |
| 긴장과 회복 | 피크 시간의 선택과 우선순위, 일이 정리된 뒤의 여유와 다음 준비 |

### 초반·중반·후반의 역할 변화

- 초반: 직접 장비를 놓고, 주문·청소를 해 보며 영업 흐름을 이해한다. 실수의 손해는 작고 복구가 쉽다.
- 중반: 첫 직원을 고용하고, 무엇을 맡길지 선택한다. 반복 업무가 줄어든 시간에 요금·메뉴·좌석 구성을 손본다.
- 후반: 단골층과 매장 특성이 생긴다. 확장과 설비 교체를 고민하고, 필요할 때 현장을 도우며 운영을 다듬는다.

성장해도 같은 클릭을 더 많이 시키는 형태는 피한다. 직원은 반복 업무를 줄이는 의미 있는 보상이다. 고용 뒤에도 직접 서비스하고 싶은 플레이어는 자발적으로 도울 수 있다.

### 시간과 리듬

한 번 접속해 20~40분 동안 영업의 변화와 작은 투자 결과를 볼 수 있게 설계한다. 이는 강제 종료 시간이 아니다. 게임 내 하루는 우선 약 12~20분으로 설정해 시험하고 일시정지·2배·4배속을 제공한다.

한산한 준비 시간, 주문이 몰리는 짧은 구간, 회복·정리 구간을 섞는다. 모든 시간에 긴급 경고가 뜨거나, 새 장비를 사기 위해 아무 일 없이 기다리는 구간이 길어지지 않게 한다.

첫 20분의 목표 경험은 ‘첫 손님 → 첫 판매 → 작은 운영 문제 → 내 선택으로 해결 → 첫 개선’이다. 재미가 검증되지 않으면 표면적인 목표 보상만 추가하지 않고, 행동의 손맛·결과의 가시성·선택지를 먼저 수정한다.

## 4. 사장다운 의사결정을 만드는 시스템

| 고민 | 선택지 | 납득할 수 있는 결과 |
| --- | --- | --- |
| 남는 돈을 어디에 쓸까? | PC 개선 / 모니터·의자 / 주방 / 현금 보유 | 고객층과 현재 병목에 따라 효과가 달라짐 |
| 저녁 주문이 밀린다 | 직원 추가 / 메뉴 간소화 / 조리 설비 추가 | 인건비·매출 기회·처리량의 교환 |
| 빈자리는 있는데 단체가 나간다 | 단체석 재배치 / 일부 좌석 확보 / 개인 손님 중심 | 연속 좌석과 평상시 가동률의 교환 |
| 이용요금을 올릴까? | 기본 요금 유지 / 프리미엄 구역 / 시간권 | 가격 민감도와 자리 품질에 따른 반응 |
| 매장을 확장할까? | 좌석 추가 / 기존 서비스 개선 / 다음 비용 대비 | 수요가 부족하면 빈 좌석과 고정비 부담 발생 |
| 야간에도 열까? | 긴 영업 / 제한 영업 / 특정 요일만 연장 | 추가 수요와 근무 비용·정비 시간의 교환 |

비싼 장비를 사면 수익이 무조건 늘어나는 구조는 사용하지 않는다. 특정 고객에게 충분한 성능을 이미 제공하고 있다면 추가 투자 효과가 작을 수 있다. 반대로 주변기기·의자·쾌적함이 더 중요한 매장도 가능해야 한다.

초기에는 다음 세 가지 운영 방향이 모두 성립하는지 살핀다.

- 합리적 가격과 단체석으로 고객을 확보하는 매장.
- 좋은 장비·모니터·쾌적함으로 객단가를 높이는 매장.
- 음식과 원활한 서비스를 강점으로 삼는 매장.

항상 한 전략이 이기도록 고정하지 않되, 투자할 때마다 정답을 무작위로 뒤집지도 않는다. 고객 요구와 피크 시간, 서비스 상태를 보고 예측할 단서를 제공한다. 새 상권과 시나리오로 다른 전략을 시험할 수 있게 확장한다.

불만·이탈·지연의 원인은 ‘가격이 부담됨’, ‘친구와 붙어 앉을 자리 부족’, ‘음식이 늦음’처럼 관찰 가능하게 보여준다. 실제로 계산된 원인을 표시하며, 결과에 맞춰 임의 설명을 붙이지 않는다.

## 5. 현실 요소는 어느 정도로 구현할까?

### 장비와 실제 게임

실제 CPU·GPU·RAM·모니터·마우스와 게임 이름을 사용해 구매와 운영의 감각을 살린다. 처음에는 몇 가지 실제 조립 구성을 추천 상품으로 제공하고 GPU·RAM·모니터·주변기기를 바꿀 수 있게 한다.

| 요소 | 구현할 수준 | 초기에는 생략할 세부 |
| --- | --- | --- |
| CPU·GPU·RAM | 실제 제품, 주요 사양, 가격, 게임별 성능 차이 | BIOS, 메모리 타이밍, 전압, 리비전별 추적 |
| 모니터·마우스·키보드 | 알아볼 수 있는 외형, 화면·입력 환경·선호 차이 | 실물 포트 위치의 치수 오차, 센서 파형·입력 지연 정밀 계산 |
| PC 구성 | 호환되는 추천 구성, 명백한 비호환 방지 | 나사·케이블·소켓을 직접 연결하는 반복 조립 |
| 실제 게임 | 제공 여부, 대략적인 요구 성능, 인기도·고객 선호 | 패치별 프레임 기록, 원작 게임 자체의 중첩 실행 |
| 고장·청소 | 원인을 알아채고 짧게 조치하거나 직원에게 위임 | 부품 단위 진단과 고장 확률의 정밀 실험 |
| 재무 | 현금, PC·음식 수익, 주요 비용, 투자·예정 지출 | 회계 전표·세무 신고·상각 방식의 세부 조작 |
| 서버·냉방 | 설비 수준·유지비·쾌적함·장애 대응 | 네트워크 패킷·유체·열역학 정밀 시뮬레이션 |

게임별 성능은 조사한 사양·성능 경향에 맞춘 간단한 모델로 시작한다. 구매 화면에서는 ‘이 게임에 충분함/부족함’, 고객층과 비용을 알아보기 쉽게 보여준다. 특정 FPS를 표시할 경우 측정값과 게임 내 추정치를 구분한다.

### 가격 기준은 유지

**2026년 1월 1일의 국내 가격을 참고 기준**으로 유지한다. 제품의 상대적인 가격·성능, PC 한 세트의 비용, 좌석 추가와 직원 고용의 부담이 실제 감각에서 크게 벗어나지 않게 한다.

당시 가격을 확인할 수 있으면 사용하고, 확보되지 않은 값은 임시 가정으로 구분해 조사한다. 근접 시점의 참고값을 사용하면 날짜를 함께 기록하며 정확한 당일 가격으로 부르지 않는다. 모든 카드 혜택·판매처·세트 옵션의 당일 증거를 수집해야만 게임 개발을 시작할 수 있다는 이전 규칙은 제거한다.

재미를 맞출 때는 시작 자본, 초기 매장 상태, 고객 유입, 영업 시간 압축, 지급 주기와 목표를 먼저 조정한다. 실제 제품 가격을 설명 없이 크게 뒤집어 놓지 않는다. 수치가 현실 참고값인지 플레이를 위한 조정값인지는 개발 데이터에서 관리한다.

사용자가 직접 정하는 PC 이용요금·메뉴 가격은 플레이어의 정책이다. 현실 가격 기준은 이런 선택까지 금지한다는 뜻이 아니다.

## 6. GTA V 느낌의 현실풍 그래픽과 최적화

여기서 GTA V는 사용자가 제시한 **시각적 현실감과 원활한 움직임의 참고점**이다. 해당 게임의 렌더러를 분석·복제했다거나 같은 수준을 달성했다는 의미는 아니다.

### 화면에서 우선할 것

한국 PC방의 실제 비율, 자연스러운 인물과 움직임, 책상·의자·바닥의 재질, 모니터 빛과 실내 조명, 생활감 있는 소품에 집중한다. 배치하고 업그레이드한 차이가 매장에 보이게 만든다.

먼저 입구·좌석 통로·카운터·주방의 대표 구도를 잡는다. 가까운 모니터·마우스·키보드는 알아볼 수 있는 외형을 유지하되, 모든 제품의 실측 복제를 출시 조건으로 삼지 않는다. 실제 사진은 분위기·비율·재질 참고에 사용하고 현장 스캔을 필수로 요구하지 않는다.

NPC의 발 미끄러짐·의자 관통·부자연스러운 앉은 자세와 화면 전체의 조명 불일치는 우선 수정한다. 잘 보이지 않는 소품 하나의 미세한 흠집보다 실제 플레이 중 반복해서 보이는 오류가 중요하다.

### 최적화 설계

| 영역 | 적용 방식 | 유지할 경험 |
| --- | --- | --- |
| 반복 가구·장비 | 같은 모델·재질 공유, 인스턴싱, 구역 단위 관리 | 많은 좌석이 있는 PC방의 밀도 |
| 거리별 품질 | 가까운 제품·인물은 상세하게, 먼 대상은 단순화 | 움직이며 볼 때 자연스러운 외형 |
| 조명 | 고정 공간의 빛은 베이크, 움직이는 대상의 그림자만 제한적으로 처리 | 현실적인 실내 명암과 접촉감 |
| 모니터 | 실제 타이틀의 화면 자료를 공유하고 거리별 갱신 빈도 조절 | 손님들이 각자 게임하는 분위기 |
| 반사 | 환경·반사 프로브 위주, 필요한 면만 추가 처리 | 플라스틱·유리·금속이 구분되는 재질 |
| 보이지 않는 영역 | 화면·구역 기준으로 그리기 생략 | 카운터·주방·통로 이동의 원활함 |
| 고객·직원 계산 | 상태 판단은 낮은 빈도로 분산, 화면 움직임은 보간 | 손님 수가 늘어도 자연스러운 이동 |
| 충돌·물리 | 걷기와 필요한 상호작용만 계산 | 사장이 매장을 이동·조작하는 감각 |
| 파일·메모리 | 압축 텍스처·모델, 구역·제품 지연 로딩, 자산 재사용 | 빠른 시작과 장시간 안정성 |

Three.js의 InstancedMesh는 같은 형상·재질을 가진 여러 물체의 렌더 호출을 줄이는 기능이다. 좌석열의 반복 제품에 적용하기 적합하다. 공간을 나눠 묶어 보이지 않는 좌석까지 불필요하게 그리지 않게 한다. [Three.js InstancedMesh](https://threejs.org/docs/pages/InstancedMesh.html)

그림자는 광원 수에 따라 추가 렌더링 비용이 생긴다. 모니터마다 그림자 광원을 생성하지 않고 고정 조명과 필요한 동적 그림자를 조합한다. 이동 가능한 가구의 그림자를 바닥에 고정해 두지는 않는다. [Three.js 그림자 안내](https://threejs.org/manual/en/shadows.html)

### 초기 성능 목표

아래 수치는 개발 예산이며 현재 달성한 결과가 아니다.

- 기준 환경: RTX 3060급 데스크톱, 1080p. 실제 시험의 CPU·RAM·브라우저도 기록한다.
- 기본 목표: 일반 영업과 만석 상태에서 60fps를 지향하고, 순간적인 긴 멈춤을 줄인다.
- 저사양 설정: 해상도·그림자·반사·장식 수준을 조절한다. 플레이 규칙과 실제 고객 수는 그래픽 옵션에 따라 바꾸지 않는다.
- 첫 플레이 필수 전송량: 약 30MB 이하를 출발 목표로 삼고 첫 조작까지의 시간도 측정한다.
- 전체 배포 자산: 우선 약 250MB 안에서 구성해 본다. 원본 자산은 별도로 보관한다.
- 검증 장면: 한산한 매장, 주문이 몰린 만석, 배치 모드, 카운터 UI 전환, 4배속.

일반 영업은 장기적으로 60석·최대 손님 60명과 직원이 활동하는 상태까지 검증한다. 평균 FPS만 보지 않고 프레임 시간 분포, UI 반응, 장시간 메모리 증가, 로딩 지연을 함께 확인한다. 빈 매장 스크린샷으로 최적화를 완료 처리하지 않는다.

## 7. 첫 완성판의 범위와 성장

1인칭 현장 운영을 기본으로 하고, 배치할 때 위에서 보는 시점과 경영 화면을 연다. 처음에는 빈 작은 매장에 첫 좌석부터 마련하고 같은 프로젝트에서 점차 확장한다.

### 작은 완성판 v0.1

- 한 매장, 0석 시작에서 12석을 채우고 24석까지 확장하는 7일 시나리오.
- 실제 제품을 활용한 몇 가지 PC 구성과 주변기기 선택.
- 손님 입장·게임 선택·시간 이용·퇴장, 단체 손님과 좌석 배치.
- 라면·음료부터 시작하는 소수 메뉴, 주문·서빙·청소.
- 첫 직원 고용·업무 배정, 간단한 고장·수리.
- 가격 조정, 주요 비용, 영업 보고서, 첫 장비 투자.
- 저장·이어하기, 기본 옵션, GitHub Pages 배포.

### 확장판 v1.0

같은 매장의 60석 확장, 직원 교대, 더 많은 실제 장비와 음식, 단골·피크 시간 변화, 30일 시나리오와 자유 운영을 추가한다. 날짜 종료는 강제 폐점이 아니라 보고·정산 시점이다.

장기 목표는 운영흑자·현금 여유·단골·매장 성장 중 여러 방향으로 달성하도록 설계한다. 좌석을 최대한 채우는 방법만 승리 조건으로 두지 않는다. 어려움이 생겨도 장비 매각·메뉴 조정·영업시간 변경으로 회복할 길을 둔다.

도시 전체, 다점포, 원작 게임 직접 실행, 세밀한 PC 조립, 멀티플레이는 첫 완성판의 범위에서 제외한다.

## 8. 제작 순서와 검증

재미·그래픽·성능을 초반부터 함께 확인한다. 제품 조사나 실사 좌석의 완벽한 복제가 끝날 때까지 영업 시스템을 미루지 않는다.

| 단계 | 결과물 | 확인할 것 |
| --- | --- | --- |
| 1. 첫 영업과 대표 화면 | 1개 좌석열·카운터, 이동, 첫 손님·주문·청소·정산, 첫 웹 배포 | 내가 운영한다는 감각, 시각 방향, 기본 성능 |
| 2. 첫 재미 | 짧은 영업, 두 가지 투자 선택, 결과가 보이는 변화, 저장 | 첫 20분의 행동과 보상, 다음 영업을 하고 싶은 이유 |
| 3. 역할 변화 | 직원 고용·자동화, 단체석·메뉴·요금 선택 | 노동이 줄고 관리할 일이 새롭게 생기는지 |
| 4. 작은 완성판 | 7일 시나리오, 0→12→24석, 목표·회복·이어하기 | 시작부터 끝까지 같은 게임으로 연결되는지 |
| 5. 확장 | 60석, 전략·단골·콘텐츠, 30일·자유 운영 | 중후반에도 의미 있는 선택과 변화가 있는지 |
| 6. 마감 | 아트·NPC·사운드·UI·최적화·저장 검수 | 만석의 실제 플레이에서 재미와 성능이 유지되는지 |

각 단계는 버릴 데모를 새로 만드는 것이 아니라 같은 게임에 기능과 품질을 쌓는 방식으로 진행한다. 초반 임시 자산을 교체할 수 있도록 제품 데이터와 화면 표현을 분리한다.

### 재미 검증 방법

초기에는 PC방에 익숙한 사람과 경영 게임에 익숙한 사람을 포함한 소수 플레이어에게 설명을 최소화하고 플레이하게 한다. 단순히 “재미있나요?”만 묻지 않는다.

- 첫 행동을 이해하는가? 막힌 곳은 어디인가?
- 어떤 투자를 골랐고 왜 골랐는가? 다른 선택도 고려했는가?
- 내가 한 변화의 효과를 알아챘는가?
- 언제 지루했거나 바빴는가? 무엇을 직접 하고 무엇을 맡기고 싶었는가?
- 다음에 개선하고 싶은 것이 스스로 생겼는가?
- 플레이를 마쳤을 때 내 매장에 애착이나 기억에 남는 일이 있는가?

첫 20분의 재미와 첫 직원 고용 후의 역할 변화가 확인되기 전에 메뉴·장비·사건 수를 크게 늘리지 않는다. 이 기준들은 재미를 보장하는 공식이 아니라 잘못된 방향을 빨리 발견하기 위한 질문이다.

### 꼭 확인할 기술 오류

좌석 중복 배정, 주문 이중 완료, 음수 재고, 선불 충전·사용의 이중 매출, 저장 복원 오류, 막힌 통로, 배속에서의 시간·정산 오류를 확인한다. 그래픽 품질 설정에 따라 매출이나 손님 판단이 바뀌지 않아야 한다.

일정은 첫 영업을 연결한 뒤 코드·에셋 제작 속도로 산정한다. 앞선 11~19주 또는 정밀 복제를 전제로 한 견적을 확정 일정으로 유지하지 않는다. 초기 계획 단위는 ‘다음에 플레이할 수 있는 변화’로 잡는다.

## 9. 기술과 GitHub 배포

| 영역 | 기본 선택 |
| --- | --- |
| 제작 | Blender, 웹용 GLB/glTF |
| 실행 | TypeScript + Vite + Three.js |
| 렌더러 | WebGL2를 기본 경로로 시작. WebGPU는 필요한 효과·성능에 이점이 확인될 때 검토 |
| 이동·충돌 | Rapier, 단순한 실내 충돌 구조 |
| 경영 UI | React + shadcn/ui, DOM 오버레이 |
| 게임 규칙 | 화면과 분리한 고객·좌석·주문·직원·경제 상태 |
| 저장 | IndexedDB + JSON 백업·가져오기 |
| 배포 | GitHub Actions로 빌드한 정적 파일을 GitHub Pages에 게시 |

시뮬레이션이 상태를 소유하고 Three.js와 UI는 표시·명령 입력을 담당한다. 렌더 프레임과 게임 시간은 분리하고, 직원과 사장은 같은 업무 상태를 사용한다. 화면 밖에서도 영업은 진행한다.

일반 플레이 화면에는 현금·시각·가동 좌석·필요한 알림만 둔다. 카운터 화면을 열면 좌석·주문·비용을 확인하고, 배치 모드에서는 시뮬레이션을 잠시 멈춘다. 카메라 입력과 메뉴 입력이 겹치지 않게 한다.

로그인·AI API·별도 게임 서버 없이 싱글플레이가 돌아가게 만든다. 자동저장과 수동 백업을 제공하고 탭이 숨겨지면 일시정지한다. 실존 게임을 카탈로그와 화면 자료로 표현하는 것과 원작을 브라우저 안에서 직접 실행하는 것은 구분한다.

GitHub Pages의 저장소 하위 경로에 맞춰 Vite의 base와 모델·텍스처·WASM 경로를 처리한다. [Vite Pages 배포 안내](https://vite.dev/guide/static-deploy#github-pages)

공식 문서상 Pages 게시 사이트 최대 크기는 1GB이고 월 대역폭은 100GB의 소프트 한도가 있다. 초기 자산 예산과 실제 접속량을 기준으로 관리한다. [GitHub Pages 사용 한도](https://docs.github.com/en/pages/getting-started-with-github-pages/github-pages-limits)

## 10. 당장 만들 결과

**작은 한국 PC방에서 첫 영업을 하고, 번 돈으로 두 가지 개선안 중 하나를 골라 매장이 달라지는 모습을 볼 수 있는 게임.**

첫 구현에서 동시에 확인할 것은 네 가지다.

1. 매장에 들어오면 한국 PC방으로 느껴지는가.
2. 조작·서빙·설치에 간단하지만 만족스러운 반응이 있는가.
3. 다음 투자를 고민하고 그 결과를 확인하는 것이 즐거운가.
4. 손님과 좌석 수를 늘려도 화면과 조작이 원활한가.

이 결과를 토대로 직원·확장·단골·다양한 장비를 쌓는다. 현실 자료는 플레이어의 판단을 설득하고, 그래픽은 매장에 애착을 만들며, 최적화는 그 경험이 계속 이어지도록 지원한다.
