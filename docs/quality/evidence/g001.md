# G001 검증 기록

날짜: 2026-09-07. 구현과 자기검토는 같은 개발 에이전트가 수행했습니다. 독립 리뷰나 사람의 재미 검증을 수행한 기록은 아닙니다.

## 구현 범위

12석 실내, 카운터·주방, Rapier 충돌, 1인칭 이동·보기·근접 확인, UI 입력 분리, 배치 미리보기, 일시정지·설정, 50ms 고정 스텝과 개발 초기화입니다. 배치 확정, 고객·장비 상품·가격·매출·음식 규칙·저장은 없습니다.

## 실행 환경과 명령

- Node 24.19.0, npm 11.9.0, 정확한 의존성은 package-lock.json.
- 로컬 `npm ci`, `npm run lint`, `npm test`(6개), `npm run typecheck`, `npm run build`, 문서·공백 검사.
- `npm run dev -- --port 5173 --strictPort` 개발 서버 시작 확인.
- GitHub Actions Ubuntu runner, Playwright 1.63.0 / Chromium 153.0.8010.12 / SwiftShader.
- production preview `/pc-cafe-simulator/`, 데스크톱 1440×900 / 작은 화면 390×844.
- 입구는 기본 품질로 캡처하고 동선 테스트는 낮음 품질로 실행합니다. UI·규칙은 같은 코드입니다.

## 확인한 결함과 수정

1. 렌더 프레임 delta를 50ms로 제한해 이동하던 초기 코드는 낮은 프레임률에서 사장의 이동 시간을 잃었습니다. 이동·방향키 시선을 sim과 같은 고정 스텝으로 옮기고 화면 위치를 보간했습니다. 초과 시간은 lag로 유지합니다.
2. 배치 모드의 DOM UI가 첫 3D 프레임보다 먼저 사용 가능해지면 마우스 광선이 이전 카메라 행렬을 사용했습니다. picking 직전에 overhead.updateMatrixWorld(true)를 호출합니다.
3. 설정 입력에 포커스가 있을 때 ESC가 무시되던 이벤트 순서를 수정했습니다.
4. 정적 장면의 그림자를 매 프레임 다시 그리지 않도록 갱신을 제한했습니다. G002의 움직이는 NPC가 들어올 때 그림자 갱신도 연결해야 합니다.

## 시각 검토와 한계

입구·좌석 통로·카운터·배치·작은 설정 화면을 Actions 캡처로 확인했습니다. UI가 매장 화면을 상시 가리지 않도록 했고 한국어 글꼴은 로컬 번들로 제공합니다. 공간은 임시 기하 형상이며, 넓은 중앙 통로·단순 의자 실루엣·강한 방향광 그림자는 G003에서 현실감과 좌석 밀도를 다듬을 대상입니다. 최종 아트 합격으로 표시하지 않습니다.

초기 캡처에서는 12석 장면이 약 52 draw calls / 24,408 triangles(기본 품질)로 표시됐습니다. 카메라·품질·그림자 패스에 따라 값이 달라지며 목표 GPU FPS 측정이 아닙니다. 현재 전체 dist는 약 7.2 MiB(파일 저장 크기)입니다. Rapier compat WASM 포함 JS 약 2.85 MB, gzip 약 1.09 MB로 Vite 청크 경고가 남습니다. 실제 네트워크 전송량·로딩 시간·GPU 메모리와 구별합니다.

로컬 Chromium 설치 서버 지연과 대체 Chromium 실행 SIGSEGV로 로컬 화면 검증은 하지 못했습니다. GitHub Actions의 실제 브라우저 결과와 캡처를 사용합니다. 탭 숨김 검사는 headless 특성 때문에 document.hidden 신호와 실제 visibilitychange 리스너를 제어한 자동 검사입니다. 실제 데스크톱의 탭 전환·복원 장시간 관찰은 별도입니다.
